# Reusable Components

Each item below is verified from source. Reuse recommendations assume a new Shopify integration layer is added in later phases and existing consumer routes are not called with fake consumer credentials.

| Path | Function/Class | Current responsibility | Inputs | Outputs | Dependencies | Reuse unchanged? | Shopify changes needed | Concerns |
|---|---|---|---|---|---|---|---|---|
| `server/utils/prunaClient.js` | `uploadPrunaFile` | Uploads an input file to Pruna. | Buffer, mimetype, filename. | Pruna file id/url/raw response. | `PRUNA_API_KEY`, fetch, safe provider endpoint. | Mostly yes. | Wrap inside server-only adapter; never expose keys to storefront. | Provider errors and upload size limits need Shopify-friendly codes. |
| `server/utils/prunaClient.js` | `createPrunaPrediction` | Starts Pruna prediction. | Model, input, optional sync flag. | Prediction payload. | `PRUNA_API_KEY`. | Yes. | Call only from worker/internal service. | Needs merchant/job correlation logs. |
| `server/utils/prunaClient.js` | `waitForPrunaPrediction` | Polls Pruna prediction status. | Prediction object, poll options. | Succeeded prediction. | Pruna status endpoint. | Yes. | Move polling to Shopify job worker. | Long poll must not block storefront request. |
| `server/utils/prunaClient.js` | `downloadPrunaOutput` / `fetchPrunaOutput` | Retrieves generated image/video bytes. | Output URL, accept/range. | Buffer/mimetype or response. | Safe fetch helpers. | Yes. | Store results in private Shopify-scoped storage. | Provider output URL retention is not a customer-facing URL. |
| `server/routes/tryons.js` | `generateProductTryOnImage` | Selects provider and generates a product try-on image. | Consumer user, catalog product, model, timer. | Generated bytes and provider metadata. | Many route-local helpers, User body photo, Product model. | No. | Extract into shared `AiTryOnService` accepting neutral person/garment inputs. | Too coupled to consumer `User` and route state. |
| `server/routes/tryons.js` | `callPrunaTryOn` | Builds Pruna try-on request and downloads output. | User, product/garment, prompt key, timer. | Generated bytes/metadata. | Pruna client, prompt utilities, stored user photo. | No. | Refactor to accept explicit person image and garment image. | Source currently assumes consumer body photo. |
| `server/routes/tryons.js` | `callFalImageEdit`, `callFalWanImageToImage`, `callFalSareeVirtualTryOn` | FAL-based image generation paths. | User, product, garment data URI, prompt/timer. | Generated bytes/metadata. | FAL env keys, route-local helpers. | No. | Extract provider clients and normalize error model. | API keys must stay server-side. |
| `server/routes/tryons.js` | `callFitRoomTryOn` | FitRoom virtual try-on integration. | User/product or garment file, cloth type, timer. | Generated bytes/metadata. | `FITROOM_API_KEY`, FormData, polling. | No. | Extract into provider module with explicit inputs. | Current cloth-type logic is product-category specific. |
| `server/routes/tryons.js` | `saveGeneratedTryOn` / `replaceGeneratedTryOn` | Persists consumer product try-on and isolation result. | User, Product, model, timer. | `TryOn` document. | `TryOn`, storage, background removal. | No. | Create Shopify-specific persistence models and retention rules. | Consumer unique index user/product is not merchant/customer safe. |
| `server/routes/tryons.js` | `saveGeneratedCustomTryOn` | Generates and stores try-on for uploaded garment. | User, garment file, prompt/category. | `CustomTryOn` document. | Multer file, storage, background removal. | No. | Store Shopify customer upload with consent/TTL. | Needs stronger privacy and deletion guarantees. |
| `server/routes/tryons.js` | `reserveToken` / `refundToken` | Debits/refunds consumer `User.tokens`. | User, timer, token cost. | Updated user or null. | `User` model. | No. | Replace with merchant-scoped usage ledger and Shopify Billing entitlement. | Direct mutation is not idempotent enough for Shopify billing. |
| `server/utils/storage.js` | `saveBuffer` | Saves bytes to local or Bunny storage. | Key, buffer, mimetype, filename. | Stored file metadata. | Local FS or Bunny env. | Partly. | Use Shopify-specific key prefixes and private/proxy delivery policy. | Current `publicUrlForStoredFile` can create public URLs. |
| `server/utils/storage.js` | `readStoredFile`, `deleteStoredFile`, `deleteStoredPrefix` | Reads/deletes stored media. | Stored file metadata/path. | Bytes or deletion result. | Local/Bunny. | Partly. | Add retention/deletion jobs per shop/customer request. | Needs auditability for compliance webhooks. |
| `server/utils/jobQueue.js` | `enqueueJob`, `enqueueJobAndWait`, `getJobStatus`, `startWorker`, `safeJobId` | BullMQ queue abstraction. | Queue/job names, data, options. | Job/status/worker. | BullMQ, Redis. | Yes with care. | Use Shopify queues and job ownership fields. | Existing `/api/jobs` assumes consumer auth. |
| `scripts/worker.js` | Worker process pattern | Starts named BullMQ workers. | Environment, MongoDB, Redis. | Running workers. | App role, queue utils. | Pattern only. | Add Shopify worker registration in Phase 4/6. | Do not mix consumer and merchant job handlers without ownership isolation. |
| `server/utils/rateLimit.js` | `createRateLimiter` | Rate limiting middleware. | Name, window, max, key generator. | Express middleware. | Request context/cache. | Yes. | Add shop/app-proxy/customer-IP key strategies. | Storefront traffic needs abuse-resistant keys. |
| `server/utils/security.js` | `isAllowedRasterImageUpload`, `normalizeRasterImageBuffer`, `safeFetchImageBuffer`, `securityHeaders` | Upload validation, normalization, safe fetch, HTTP headers. | Files, URLs, buffers, Express req/res. | Validated/normalized buffers or middleware effects. | Sharp/fetch. | Partly. | Add Shopify app proxy HMAC and customer consent flow. | Need verify SVG/script rejection for storefront uploads. |
| `server/utils/backgroundRemoval.js` | `isolateSubjectAsset` | Produces transparent subject assets. | Stored source image/user context. | Processed image/metadata. | Python/service configuration. | Partly. | Decouple from consumer user assumptions and TTL results. | Expensive; should run in worker. |
| `server/models/TryOn.js` | `TryOn` model / `tryOnToClient` | Consumer product try-on record and client projection. | Mongoose document. | Stored record/client JSON. | Mongoose, media token signing. | No. | Create `ShopifyTryOnJob` and `ShopifyTryOnResult` models. | Unique index and media URLs are consumer-specific. |
| `server/models/CustomTryOn.js` | `CustomTryOn` model | Consumer uploaded garment try-on history. | User, garment/result metadata. | Stored record/client JSON. | Mongoose. | No. | Use only as schema inspiration. | Contains consumer user ownership. |
| `server/models/ExternalTryOn.js` | `ExternalTryOn` model | Consumer external product try-on history. | User, source URL, image URL. | Stored record/client JSON. | Mongoose. | No. | Shopify products should use Admin API product IDs/media IDs. | External URL uniqueness is not enough for Shopify variants. |
| `server/routes/payments.js` | Razorpay/PhonePe/Apple payment flows | Consumer token purchase and subscription logic. | Consumer auth/payment payloads. | Orders, credits, subscription snapshots. | Razorpay, Apple, TokenOrder, User. | No. | Replace with Shopify App Billing. | Reusing this would violate requested billing boundary. |
| `server/services/creditLedger.js` | `applyCreditLedgerEntry`, `creditUser`, `debitUser` | Idempotent-ish consumer credit ledger helper. | User id, tokens, action, metadata. | User and credit event. | User, CreditEvent. | No for direct use. | Build merchant-scoped ledger with shop id, subscription id, idempotency key. | Existing ledger targets consumer users. |
